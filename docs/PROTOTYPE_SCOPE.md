# Hwanjo v2 프로토타입 기획 기준

Step 0 출처는 `HWANJO_V2_STEP0_SETUP.md` 4절이다. 후속 사용자 요청으로 Element Lab v0.1 구현·검증·Windows 빌드가 허용되었다. 최신 입력은 `docs/02_PROTOTYPE_SPEC.md`, `docs/01_ART_DIRECTION.md`, `docs/03_CODEX_IMPLEMENT.md`, `docs/04_QA_CHECKLIST.md`다. 패키지는 안내된 하위 폴더 대신 `docs/`와 루트 `element-lab-v01/`에 배치되어 있으며 원본은 이동·수정하지 않는다. 이 문서를 확정 기준과 실제 채택한 임시값의 단일 작업 기준으로 유지한다.

## 확정된 이번 실험의 기준

- 목적: 탐험용 속성 반응과 검흔 재타격이 이해하기 쉽고 응용할 수 있는지 검증한다.
- 동양풍과 사방신을 유지하되 같은 인간 플레이어와 근접 검 하나를 사용한다.
- 4무기/2폼 장착/퀵스왑 게이지/출발 폼 잔향/현무 전용 패링을 가져오지 않는다.
- 이번 테스트 속성: 불 / 물 / 바람 / 얼음.
- 기본 베기: J 짧게, 단타 1회.
- 차지: J Hold, 차지 기준 0.5초.
- 차지 단독 최대 도달거리: 기본 베기 R의 1.75배. 동일 플레이어 기준점에서 잰 전체 도달거리이며 검 끝의 추가 이동량이 아니다.
- 동시에 존재하는 검흔: 1개.
- 속성 전환: 1=불, 2=물, 3=바람, 4=얼음. 즉시 선택, 전환 연출/쿨타임 없음.
- 반응: 한 입력으로 상태 변화 최대 한 단계. 같은 입력에서 건조 후 점화까지 연쇄하지 않는다.
- 검흔: 차지 뒤 공간에 남긴 반응 대상. 다른 속성의 베기가 실제로 닿아야 반응한다.
- 대상 이름보다 특성(Trait)·현재 상태(State)·입력 효과(Effect)로 공통 반응을 판정한다.
- 가연성은 특성, 건조/젖음은 상태로 구분한다.

## 사용자가 추가로 요청한 범위

- 특성을 직접 바꾸는 더미 박스 1개와 테스트 UI. 프리셋·재질은 드롭다운, 동시에 가질 수 있는 특성은 다중 선택/토글이 가능한 구성 후보다. Apply/Reset 및 현재 효과·반응·상태 표시가 필요하다.
- 상태 변화를 읽을 수 있는 VFX, 기본 타격감과 프로토타입 시각 품질.
- 기본 적에게도 속성 반응을 적용한다. 불은 연소와 지속 피해, 물은 이동 및 공격 속도 둔화, 바람은 넉백과 작은 상승, 얼음은 동결이다. 후속 명세의 기본 적 IntrinsicMoisture와 구체 임시값을 아래 표에 채택했다.
- 사용자 캐릭터 레퍼런스에 맞춘 약 48×48 동양풍 픽셀 캐릭터와 필요한 애니메이션. 후속 요청에서 원본 5장이 제공되었으며 2026-09-24 실제로 모두 열어 보고 SHA-256 일치를 확인했다. `element-lab-v01/`의 Character(REF01)는 검은 묶음머리·붉은 스카프·남색/아이보리 의상, Stage1(REF02)는 작은 주인공과 청록 숲 유적 비율, 4Concept(REF03)는 동양풍 건축·깊이감, VFX1/VFX2(REF04/05)는 궤적·준비/접촉/회수 강약의 기준이다. 원본의 쌍검·대도·3타·백발 폼·호랑이 소환은 구현하지 않는다.

## 후속 Element Lab 요청에서 채택한 제작 범위

- 작은 반응 실험실과 짧은 응용 구간. 큰 메트로베니아 월드 제작은 하지 않는다.
- 환경 후보: 덩굴·밧줄·나무상자·물웅덩이·풍차/송풍 장치·얼릴 수 있는 가동 장치.
- 검흔의 우선 비교: 불 검흔+바람, 물 검흔+얼음.
- 타격 판정 표시, 최근 반응 기록, 대상 초기화, 실험실 전체 Reset.
- 적 1종부터 시험. 보스·스토리·저장·해금 동선은 이번 제작에서 제외한다.

## 최종 결정으로 남겨 둔 항목

임시 타이밍·거리·검흔 수명과 퍼즐 난이도, 사방신과 속성의 대응, 생성 아트의 팀 승인·실제 사용 권리는 아직 최종 확정이 아니다. 플레이 UI는 불/물/바람/얼음 명칭만 사용한다. 원본 레퍼런스 자체를 빌드 리소스로 복사하지 않는다.

환경 확인 결과와 다음 작업 상태는 각각 [ENVIRONMENT_AUDIT.md](ENVIRONMENT_AUDIT.md), [HANDOFF.md](HANDOFF.md)에 기록한다. 이 문서에 구현·검증 완료를 추정해 기입하지 않는다.
