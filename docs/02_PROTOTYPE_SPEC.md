# 02 · Hwanjo v2 Element Lab v0.1 — 구현 명세

작성: 2026-09-24. 새 기획의 **작은 속성 반응 실험실**이다. 이전 CombatPrototype v0.1~v0.6과 버전 축이 다르다.
현재 요청과 임시 구현안을 분리한다. 이 문서의 규칙을 실행 요청으로 채택하더라도 팀 전체의 최종 게임 규칙으로 표시하지 않는다.

## 1. 사용자가 확정한 이번 테스트 기준

| 항목 | 확정 기준 |
|---|---|
| 속성 | 불 / 물 / 바람 / 얼음 |
| 기본 공격 | J 짧게, 근접 검 하나로 단타 1회 |
| 차지 | J Hold 0.5초 |
| 차지 도달거리 | 기본 베기 R의 1.75배. 같은 기준점의 전체 전방 도달거리 |

| 제외 | 폼체인지·4무기·QS·잔향·현무 전용 패링·보스·큰 월드·저장/성장 시스템 |

## 2. 아직 빈칸인 부분의 첫 구현안

**아래는 이전에 사용자가 확정한 사실이 아니다. 이번 제작을 시작하기 위한 임시값이다.**
로컬 `docs/PROTOTYPE_SCOPE.md`에 이 구분을 옮겨 최신 단일 기준으로 관리한다. 실제 값은 하나의 튜닝 데이터로 조정 가능하게 한다.

| 항목 | 임시 시작안 | 이유·확인할 것 |
|---|---|---|
| 탭/홀드 실행 | J를 놓을 때 0.5초 미만이면 단타, 이상이면 차지 베기 1회 | 입력 하나에 기본공격+차지가 이중으로 발생하지 않음. 탭 지연은 QA에서 확인 |
| 누르는 동안 | 준비 상태만 표시. 0.5초에서 명확한 준비 완료 신호. 자동 발사하지 않음 | 길게 눌렀다고 반복 발사하지 않음 |
| 차지 중 행동 | 지상 이동은 평소의 50%, 점프·대시·피격·사망은 차지를 취소 | 지상 차지부터 시험. 공중 단타 허용, 공중 차지는 이번 기본값 OFF |
| 속성 선택 시점 | 선택은 즉시 반영, 실제 베기를 발동하는 순간 속성 고정 | 한 공격 도중 숫자키를 바꿔도 판정의 속성이 중간에 바뀌지 않음 |
| 검흔 수명 | 2초. 튜닝 가능 | 최대 1개만 확정됐으며 2초는 시작값 |
| 검흔 위치 | 재타격 면이 약 0.75R~1.0R에 걸치게. 전체 외곽은 1.75R를 넘지 않게 | 단타 R로 제자리에서 반응 가능. 정확한 모양은 시각·판정 함께 확인 |
| 새 차지 | 이전 검흔·그 슬롯의 변환물을 먼저 종료하고 새 검흔 생성 | 숨겨진 중복 슬롯 방지 |
| 검흔 변환 | 동일 슬롯·최초 만료시각 유지 | 물↔얼음으로 바꿔 수명 무한 갱신 금지 |
| 한 단계 의미 | 하나의 의미상 상태 전이. 소화+젖음은 `Burning→Wet` 한 전이로 취급 | 내부 플래그 여러 개를 바꾸는 것은 가능. 같은 입력의 `Wet→Dry→Burning` 재평가는 금지 |
| 기본 적의 얼음 반응 | 내부 수분을 가진 Freezable 대상 설정으로 **젖지 않아도 짧게 동결** | 사용자의 ‘얼음=적 얼림’ 요청 우선. ‘젖은 적만 동결’은 후속 비교안이며 이번 기본값 아님 |
| 입력 비용 | 마나·소모품 없음. 동작 회수시간과 단타/차지 제한만 | 퍼즐 실패로 자원이 바닥나지 않게 함 |

새로운 사용자 결정과 충돌하면 해당 항목을 임시값으로 강행하지 않는다.
R의 실제 길이·피해·회수시간·이동속도는 현재 스케일에 맞게 작은 값부터 선정하여 표에 기록한다.

## 3. 씬 범위

새 씬: `Hwanjo_v2_Test/Assets/ElementLab/Scenes/ElementLab.unity`.
기존 SampleScene/Settings를 지우지 않는다. 한 씬에 작은 구역을 놓고 표지판/리셋으로 이동한다.

| 구역 | 내용 | 성공 기준 |
|---|---|---|
| 조작 | 이동·점프·대시, 기본/차지, 1~4, R·Esc | 입력이 읽히고 차지가 정확히 한 번 나감 |
| 더미 실험 | 편집 더미 1개 + 런타임 패널 | 프리셋·특성·상태를 바꾼 결과를 바로 확인 |
| 환경 반응 | 덩굴·밧줄·나무상자·물웅덩이·풍차·결빙 장치 | 공통 규칙을 공유하며 서로 다른 결과 |
| 검흔 | 불→바람, 물→얼음, 소화·해동·반응 없음 | 단독 사거리와 확장 반응을 구분 |
| 적 | 같은 적 1종, 짧은 예고 후 단순 공격 | 4속성 반응과 검의 피해를 구별 |
| 작은 응용 | 닿지 않는 가연성 밧줄 + 사다리/다리, 별도의 작은 동결 구역 | 규칙을 배운 뒤 1~2문제를 스스로 해결 |

모든 속성은 이 실험실에서 처음부터 사용 가능하다. 최종 게임의 해금 순서는 구현하지 않는다.
큰 맵·컷씬·다수 보스·동물 소환·인벤토리·NPC 대사 시스템은 추가하지 않는다.

## 4. 반응 구조

`Action/Emitter → EffectEvent → Target Traits + State snapshot → Reaction → Consequence + Presentation`.
실제 C# 이름은 코드 구조에 맞춰 정한다. 한 클래스에 모든 오브젝트 이름 조건문을 넣지 않는다.
권장 분리는 공통 반응 판정, 상태 저장, 물리 이동, 개별 결과, 표현이다. 과도한 범용 엔진/DOTS/ECS 도입은 하지 않는다.

### 4.1 입력/특성/상태

- 입력: Heat / Moisture / Cold / WindImpulse. `Moisture`는 입력이며 `Wet`은 결과 상태다.
- 특성: Flammable, Wettable, Freezable, Meltable, Extinguishable, Pushable, WindReactive.
- 동결 요건 데이터: `WetOrLiquid` 또는 `IntrinsicMoisture`를 대상 설정으로 둔다. 별도 적 이름 하드코딩은 금지.
- 상태: 수분(Dry/Wet/대상에 해당 없음), 연소 여부, 동결 여부, 물 자체의 Liquid 여부. 한 enum으로 모든 값을 억지로 배타 처리하지 않는다.
- Dry/Wet 동시 활성 금지. Burning/Frozen 동시 활성 금지. 물 자체의 Liquid와 동결은 동시에 활성화하지 않는다.
- 고정/구속은 이동 허용 정보다. Frozen이면 모두 Rigidbody를 정지시키는 전역 규칙은 만들지 않는다.
- 물리 피해·반응 피해·타격 시각효과는 별개다. 속성 반응 없음은 ‘검에 맞아도 피해가 없음’이 아니다.

### 4.2 같은 입력 한 단계 보장

J를 눌렀다 놓아 실제로 실행된 베기 하나에 ActionId 하나를 부여한다. 한 대상의 여러 collider가 닿아도 물리 타격 1회, 반응 판정 1회가 기준이다.
한 입력으로 여러 대상을 맞히는 것은 허용한다. 각 대상은 입력 전 snapshot에서 반응을 결정하고 결과를 한 번 적용한다.
`Wet→Dry` 처리 후 같은 입력을 다시 평가해 `Dry→Burning`을 호출하지 않는다.
DoT는 Health 피해만 처리하고 Heat 이벤트를 재발행하지 않는다.
새 검흔은 자기를 만든 베기에 즉시 재타격되지 않는다. 이후 별도 ActionId의 베기로만 반응한다.
바람으로 발사된 전달체도 원래 반응 사건 계보와 대상별 방문 기록을 갖게 하여 한 대상에 건조+점화가 한꺼번에 발생하지 않게 한다.

### 4.3 이번 실험의 반응표

EL 번호는 **이 패키지 내부 추적용**이다. Notion의 R00~R10을 자동으로 같은 번호로 대체하지 않는다.
아래는 미정 표를 첫 실험을 위해 좁힌 구현안이며 최종 게임 합의가 아니다.

| ID | 입력과 조건 | 결과 / 우선순위 |
|---|---|---|
| EL01 | Heat + Frozen + Meltable | 해동 1회. 물 자체는 Liquid, Wettable 고체/적은 Wet으로 복귀. 즉시 건조·점화 금지 |
| EL02 | Heat + Wettable + Wet, Frozen/Burning 아님 | Wet 제거→Dry. 그 입력에서는 끝 |
| EL03 | Heat + Flammable, Wet/Frozen/Burning 아님 | 점화→Burning. Dry가 해당되지 않는 대상은 ‘젖지 않음’으로 검사 |
| EL04 | Moisture + Extinguishable + 활성 불/Burning | 소화. Wettable 몸체는 Wet, 불 검흔은 종료. 한 의미상 전이 |
| EL05 | Moisture + Wettable, Frozen/Burning 아님 | Dry→Wet, 이미 Wet이면 효과 중첩 없이 수명 갱신 |
| EL06 | Cold + 활성 불/Burning + Extinguishable | 소화만. 같은 입력에서 동결까지 진행하지 않음 |
| EL07 | Cold + Freezable, Frozen/Burning 아님 | Wet/Liquid 또는 IntrinsicMoisture 조건 충족 시 Frozen. 대상별 결과 실행 |
| EL08 | WindImpulse + Pushable + 현재 이동 허용 | 충돌을 지키는 전방 밀림. 적 프로필만 작은 상승을 함께 사용 |
| EL09 | WindImpulse + WindReactive | 대상의 바람 반응 1회: 장치 회전, 불/물 검흔 전달. EL08과 같은 힘을 두 번 적용하지 않음 |
| EL10 | 연소 시간/연료 종료 이벤트 | 덩굴 제거·밧줄 해제·상자 파괴 등 개별 결과 |
| EL00 | 지원 규칙이나 요건 없음 | 반응 없음. 디버그에 이유 표시 |

Heat: 해동→건조→새 점화 순으로 조건을 먼저 고르고 하나만 적용한다.
Cold: 소화 가능 불이 있으면 소화만, 없으면 동결 요건 검사.
WindReactive+Pushable을 같이 켠 경우 반응 설정의 `Device / TraceTransport / BodyPush` 중 선택한 경로만 쓰는 시작안이다.
이미 Burning인 대상에 Heat를 더해도 강화·수명 리셋하지 않는다. 이미 Frozen인 대상에 Cold는 중첩·수명 갱신하지 않는다.
물 자체에 Heat로 증발시키기, 물을 임의 유체로 계속 늘리기, 자동 산불 확산은 이번 기본 범위 밖이다. 이 미지원은 첫 실험의 범위 선택이며 최종 세계 규칙으로 확정하지 않는다.
반응 없음의 사유를 `NoTrait / WrongState / Immovable / RehitBlocked / Unsupported` 등으로 기록한다.

## 5. 더미 박스 런타임 Inspector

Editor Inspector에만 넣지 않는다. **Windows 실행 파일에서 마우스로 바꿀 수 있어야 한다.**

| 설정 | UI·동작 |
|---|---|
| Preset | Custom / Dry Vine / Wet Vine / Wooden Box / Water / Wind Device / Freezable Device |
| Material | Plant / Wood / Metal / Water / Custom. 프리셋 초기값용, Material 이름으로 공통 반응 분기 금지 |
| Traits | 일곱 특성을 독립 토글. 여러 개 동시 선택 가능 |
| 초기 상태 | 수분·연소·동결을 분리. 물 자체의 Liquid 설정은 해당 프리셋에서 표시 |
| 동결 조건 | WetOrLiquid / IntrinsicMoisture 드롭다운 |
| 이동·바람 | Fixed 여부, BodyPush / Device / TraceTransport 중 지원하는 결과. 더미가 지원 못하는 결과는 설명과 비활성화 |
| Apply | 유효성 검사 후 적용. 기존 대상의 진행 중 타이머·피해·이동·VFX를 초기화해 새 시험 시작 |
| Reset Target | 마지막 Apply 값으로 복원. 시스템 기본값과 구분 |
| Default Preset | 최초 프리셋 복원 별도 버튼 |
| 관찰 | 현재 특성·상태, Last Effect, EL 규칙 ID, Before→After, ‘반응 없음’ 이유, 최근 8개 이력 |

충돌하는 조합을 조용히 고치지 않는다. 오류를 설명하고 Apply를 막는다.
Flammable인데 소화 불가능한 조합처럼 게임적으로 허용은 가능하지만 불편한 설정은 경고와 함께 허용한다.
Dry+Wet, Burning+Frozen, 물 자체 Liquid+Frozen 같은 저장 모순은 차단한다.
더미 패널 열기/편집 중 월드는 일시 정지하고 UI는 작동하게 하는 시작안이다. 패널 닫을 때 이전 게임 속도를 복원한다.
UI 클릭·입력창 포커스가 공격·숫자 속성 선택·R 리셋으로 전파되지 않게 한다.
더미의 디버그 Apply는 게임 반응 한 단계 규칙을 우회하는 편집 동작임을 명시한다.

## 6. 환경 6종과 리셋

| 대상 | 초기 설정 | 결과 |
|---|---|---|
| 덩굴 | Flammable, Wettable, Extinguishable / Dry | 점화·젖음·소화 공통 규칙, 연소 완료 후 통로 비움 |
| 밧줄 | 덩굴과 동일 특성·상태 | 점화 규칙 동일, 완료 후 사다리/다리 지지 해제 |
| 나무상자 | 위 특성+Pushable / Dry | 타거나 밀림. 기본값에서 젖었다고 질량이 자동 증가하지 않음 |
| 물웅덩이 | Freezable, Meltable / Liquid | 수면 동결 시 고정된 표면 발판, 해동 시 원래 물 |
| 풍차 | WindReactive / 고정 몸체 | 바람 입력에 회전. 물리적으로 몸체가 날아가지 않음 |
| 결빙 장치 | Wettable, Freezable, Meltable / Dry, 작동 중 | 물→Wet, 얼음→Frozen·정지, 불→해동·재가동 |

풍차는 우선 회전 확인까지 만든다. 상승기류를 추가한다면 명시된 송풍 장치 한 개에만 한정하고 임시 높이·조건을 기록한다. 허공 바람 공격=상승기류는 금지.
R은 오브젝트·적·플레이어·검흔·남은 타이머·물리 속도·UI 이력을 초기 상태로 복원한다. 소실된 대상도 복원해야 한다.
프로토타입에서는 저장을 구현하지 않는다. 진행 불능 방지는 리셋과 안전한 응용구역 출구로 해결한다.

## 7. 검흔 최소 반응

### 7.1 공통 수명과 충돌

차지 단독의 판정/접촉 외곽은 1.75R를 넘지 않는다. 수명이 있는 검흔이 자동으로 멀리 움직이지 않는다.
검흔 자체는 처음에는 장식과 상호작용 collider만 갖고, 주변 적을 매 프레임 때리는 피해 장판이 아니다.
같은 속성으로 때려도 강화·복제·수명 갱신하지 않는다. 지원 안 하는 조합은 ‘이번 실험 미지원’으로 표시한다.
좌우 방향·벽 충돌·만료·리셋을 모두 시험한다.

### 7.2 불 검흔→바람

불 검흔을 다른 ActionId의 바람 기본 베기로 실제 맞히면 원래 검흔을 소비하고 화염 전달체 1개를 보낸다.
방향은 재타격한 검의 진행 방향. 벽을 뚫지 않는다. 물 검흔도 같은 전달 로직으로 수분을 전달하는 작은 확장까지 허용한다.
추가 비행거리는 생성 지점 기준 3R를 임시 시작값으로 둔다. **1.75R는 단독 차지 사거리이지 바람 후 비행거리의 상한이 아니다.**
첫 유효 대상 또는 지형에 닿으면 종료. 그 대상에 Heat 또는 Moisture 사건 1회. 다중 collider 중복 금지.
전달체도 같은 플레이어 검흔 슬롯의 사용 중 산출물로 센다. 새 차지를 만들면 이전 전달체가 남아 중복 존재하지 않도록 종료한다.
환경 상대의 상태를 재검사한다. 불을 보냈다고 젖은 덩굴을 바로 태우지 않는다: 젖었다면 Dry로만 변한다.

### 7.3 물 검흔→얼음 / 얼음→불

물 검흔은 Freezable+Liquid로 공통 동결 규칙을 사용한다. 동결 결과는 동일 슬롯의 얼음 구조로 변환한다.
첫 버전은 **지면/지정 수면 가까이의 생성만 발판으로 허용**한다. 위에 기존 검흔/얼음 구조를 지지면으로 사용한 공중 계단 쌓기는 금지.
허용 지지면이 없으면 동결 모양은 보이되 발판 충돌을 만들지 않고 HUD에 이유를 표시한다. 임의 순간이동으로 지면에 끌어붙이지 않는다.
허용 거리·두께는 R 기준 작은 임시값을 정해 문서화한다. 고정 수면 얼음과 자유 생성 검흔의 조건은 분리한다.
열로 해동하면 물 검흔으로 바뀌며 현재 전달 속성·특성·VFX·collider를 함께 갱신한다. 최초 만료시각은 보존한다.
임시 검흔/얼음의 원래 2초 수명은 짧은 테스트값이다. 실제 퍼즐용 유지시간을 보장하는 최종 결정이 아니다.

### 7.4 나머지

불 검흔+물/냉기: 소화 후 제거. 물 자체+불: 첫 실험 반응 없음. 같은 속성: 유지, 강화 없음.
바람 검흔은 방향이 보이는 짧은 흔적을 생성하되 새 복합 마법은 추가하지 않는다. 2차 합성 없음으로 디버그 표시한다.
얼음 검흔+바람은 이동 가능한 빙편 프로필일 때만 EL08로 처리할 수 있으나 첫 버전에서는 고정형으로 시작한다.
12가지 순서별 별도 기술을 만들지 않는다.

## 8. 적 1종의 속성 결과

작은 근접 적 한 종류. 순찰/접근→분명한 예고→공격→회수. 새 보스·원거리 AI·패링 시스템은 만들지 않는다.
기본 적에는 Flammable/Wettable/Extinguishable/Freezable/Meltable/Pushable과 동결 요건 IntrinsicMoisture를 설정한다.
이는 게임 데이터 선택이며 실제 생물학 시뮬레이션을 뜻하지 않는다.

| 결과 | 임시 시작값 | 규칙 |
|---|---|---|
| 검 단타 피해 | 10, 적 HP 100 | 속성 반응과 별개. 차지 피해도 첫 비교에서 10으로 유지 |
| 불 | Burning 3초, 0.5초 간격 피해 2, 최대 6틱 | 같은 Heat로 무한 지속 연장 없음. Wet이면 그 타격은 건조만 |
| 물 | Wet 2초, 이동 속도·공격 동작 진행속도 ×0.8 | 중첩 없음, 다시 물이면 지속시간만 갱신. 전역 Time.timeScale 사용 금지 |
| 바람 | 수평 밀림 약 1R 이내, 아주 짧은 상승 | 도망갈 정도의 큰 런처 아님. 지면·벽·천장 충돌 우선, 물의 둔화가 넉백·중력까지 약하게 하지 않음 |
| 얼음 | Frozen 0.8초 | 일반 적은 직접 동결. 공격·자발 이동 중지, 중력 유지. 얼린 후 추가 물리 피해 가능 |
| 재동결 제한 | 해제 후 0.6초 | Cold 연타만으로 영구 정지하는 테스트 왜곡 방지. 디버그에서 제한 이유 표시 |
| 바람 재부양 제한 | 0.5초 | 입력 1회와 다중 collider로 상승이 누적되는 버그 방지 |

동결되면 적의 진행 중 공격을 취소해 얼어 있는 적이 숨은 공격 판정을 내지 않게 한다.
해제 후에는 준비 단계를 다시 거치고 즉시 숨은 타격을 이어가지 않는다.
물의 공격 둔화는 논리 타이밍·보이는 공격 애니메이션을 함께 늦춘다. 준비 시간만 변경하고 판정 시간을 그대로 두지 않는다.
Heat로 얼음을 해동하면 Wet으로만 돌아가며, 같은 타격에서 화상까지 발생하지 않는다.
물/동결 종료는 효과 출처별 modifier를 제거해 원래 속도를 복구한다. 중첩 해제 순서로 이동속도가 영구 감소하지 않게 한다.

## 9. 디버그와 테스트 가능성

기본 제안: A/D 이동, Space 점프, Shift 대시, J 탭/홀드, 1~4 속성, R 전체 초기화, Esc 일시정지.
F1: 판정·상태 표시. F2: 더미 편집기. F3: 타격감 ON/OFF. 충돌하는 기존 입력이 있으면 보고 후 최소 조정.
F4/F5 같은 빈 키에 예전 QS 충전·폼 선택 기능을 되살리지 않는다.

반응 로그: Target ID, 입력 출처, ActionId, 입력 Effect, Before State, 규칙 ID, After State, 무효 사유.
최근 8개는 HUD, 전체 결과는 이번 실행 artifacts에 선택 저장한다. 사람의 개인정보는 기록하지 않는다.
실험실 UI에서 모든 핵심 튜닝을 찾을 위치를 문서에 적는다. 실시간 조정은 적어도 더미 특성·상태와 GameFeel에 제공한다.

## 10. 범위 종료

성공 목표는 ‘메트로베니아 완성’이 아니라 **단타/차지/검흔 조작 + 공통 반응 + 편집 더미 + 적 효과 + 작은 응용 + 읽히는 아트/VFX**다.
최종 승인 전 큰 월드·반응 30종·복잡한 상태이상·대규모 물리 시뮬레이션을 추가하지 않는다.
기술 검증과 사람이 느끼는 직관성·재미·미술 승인은 따로 보고한다.
