## D. 구현 단계

기본적으로 한 주 에이전트가 단계별로 통합한다. 대규모 병렬화·worktree 자동화·커밋 게이트를 이번에 새로 만들지 않는다.
각 단계에서 컴파일/관련 테스트를 확인하고 다음으로 진행한다. 정상 진행 시 매 단계마다 사용자 답변을 기다릴 필요는 없다.

### 1. 공통 반응 기반 + 더미

Trait/State/EffectEvent/Reaction/Consequence를 과하지 않게 분리한다.
타입 이름별 정답표가 아니라 특성·현재 snapshot으로 판단한다.
한 ActionId·대상당 한 반응, 복수 collider 중복 차단, 열의 해동/건조/점화 우선순위를 테스트한다.
런타임에서 설정 가능한 더미 박스와 프리셋/다중 특성 토글/상태/Apply/Reset/반응 이력을 만든다.
덩굴과 밧줄이 같은 점화 규칙을 공유함을 테스트로 보여준다.

### 2. 플레이어 + 차지 + 검흔

02 명세의 단타·0.5초·1.75R·최대1개·1~4 선택을 정확히 적용한다.
차지 시작에 평타를 미리 발생시키지 않는 release 판별 방식부터 구현한다.
물리 이동·검의 Damage·Effect·VFX 수명을 분리한다.
불→바람 전달, 물→얼음 변환, 해동/소화/미지원 반응을 만든다.
검흔이 R로 다시 닿는지, 1.75R 외곽을 넘지 않는지 실제 좌표와 화면에서 확인한다.
대시·점프·피격·패널 포커스에서 입력/차지 상태가 남지 않게 한다.

### 3. 환경 + 적 + 작은 응용

한 테마, 환경 6종, 기본 적 1종, 응용 문제 1~2개까지.
적의 물 둔화는 animation과 hit timing을 함께 바꾼다. 전역 timeScale로 적만 느리게 만들지 않는다.
기본 적은 요청대로 직접 짧은 동결이 되도록 대상 설정의 IntrinsicMoisture를 사용한다.
얼음의 wet-only 모드를 기본값으로 몰래 대체하지 않는다.
바람은 짧은 수평 밀림+작은 상승으로 시작한다. 무한 재부양과 지형 관통은 방지한다.
R 전체 리셋, F1 진단, F2 더미 패널, F3 타격감 비교를 구현한다.

### 4. 캐릭터·애니메이션·VFX

게임 로직이 검증되면 임시 캐릭터를 REF01 기반의 같은 인간 캐릭터로 제작·연결한다.
REF04/05는 모션 강약·속성 궤적을 참고한다. 단타인데 3번 피해나 3타 애니메이션이 자동 실행되면 안 된다.
물·바람은 완성 원본이 없으므로 01의 제안으로 새로 만들고 그 사실을 기록한다.
이미지 입력/생성 도구가 이 세션에 있는지 실제 확인한다. 도구가 없거나 반복 생성으로 기준을 못 맞추면 fallback과 누락을 기록하되 기능 검증은 계속한다.
가용한 내장 이미지 생성 도구를 활용한다. 기본 생성 한도와 비용 경계는 01을 따른다.
Run·단타·Charge Release의 준비/접촉/회수 포즈를 우선한다. 첫 포즈와 단타를 보지도 않고 수십 개 clip을 대량 생산하지 않는다.
Sprite/칼/궤적/검흔/상태 overlay의 위치와 종료를 실제 런타임에 연결한다.

### 5. 통합 검증 + Windows 빌드

컴파일, EditMode, PlayMode, 빌드, 렌더링, UI 클릭, 실제 입력을 검증한다.
테스트 XML의 총 실행 수와 성공/실패/skip을 읽는다. 파일 존재나 process exit 0만으로 통과를 단정하지 않는다.
빌드 출력: `Builds/ElementLabV01/HwanjoElementLab.exe`와 함께 필요한 폴더 전체.
한 번에 Unity Editor 하나만 실행한다. 그래픽 캡처 검증에서 `-nographics`를 쓰고 화면이 없다고 성공 처리하지 않는다.
실제로 남긴 게임 PNG와 필요하면 짧은 연속 프레임을 열어본다. AI 컨셉 이미지를 게임 화면으로 표시하지 않는다.
런타임 검증용 게임/Editor는 정상 종료를 우선하며, 문제가 있을 때 이 작업이 시작한 프로세스만 구분한다.

## E. 문서·로그와 복구

프로젝트 튜닝값과 선택한 임시 규칙을 `docs/PROTOTYPE_SCOPE.md`에 기록한다.
실제 명령, exit code, 테스트 XML, 빌드, 캡처, 알려진 문제는 `docs/PROTOTYPE_VALIDATION.md`에 기록한다.
새 Art manifest에는 원본 참고 ID, 실제 파일 경로, 프레임 크기/수, pivot/PPU, 생성·가공 방법, fallback 여부를 기록한다.
`docs/HANDOFF.md`에 마지막 검증 지점과 재개할 단계·남은 파일을 남긴다.
로그 위치: `artifacts/element-lab/<run-id>/`.

PowerShell 상대경로와 .NET 프로세스 현재 경로를 혼동하지 않는다. 파일 I/O는 확정된 절대 경로를 사용한다.
Git stdout(목록)과 stderr(경고)를 합쳐서 삭제 파일이나 실패 목록으로 해석하지 않는다.
CRLF/BOM 경고와 compile 실패를 구분하며, 의미 없는 인코딩/빈줄 재작성으로 시간을 쓰지 않는다.
실패한 테스트를 삭제·skip하거나 expected 값을 버그에 맞추어 통과시키지 않는다.

## F. 완료 보고

다음 항목을 구분해 한국어로 보고하고 멈춘다. 자동 Git 작업은 하지 않는다.

1. 전체 상태: PASS / PARTIAL / BLOCKED. PASS는 아래 모든 필수 기술·리소스 기준 충족을 뜻하며 팀 아트 승인은 별도.
2. 기능: 구현한 반응·검흔·더미·적·UI. 실제 값과 임시 결정 목록.
3. 검증: compile/test/build/runtime/화면/UI 항목 각각의 성공 여부와 근거 경로.
4. Art: 실제 재생 애니메이션, 사용한 5개 참고 ID, fallback·누락·미검수 부분.
5. 실행 파일·씬·조작·튜닝 위치.
6. git status와 변경 파일 범위, 사용자/원본 보존.
7. 사람 플레이테스트가 필요한 질문 3개.

명세의 필수 기능이 빠졌으면 PARTIAL. 환경/컴파일/치명적 런타임 실패로 유효한 빌드가 없으면 BLOCKED.
이미지 5장을 못 읽었는데 읽었다고 하거나, 생성한 clip 수만으로 ‘아트 완성’이라 보고하지 않는다.
결과 JSON을 별도 생성할 수는 있지만, 그것을 근거 XML/로그 없이 자동 통과시키는 새 런처는 만들지 않는다.
