# v0.3 · 실제 검증과 인계 기준

이 문서는 **해야 할 검사**다. 아래 체크박스나 과거 v02 PASS 보고는 이번 실행의 통과 증거가 아니다.
v02의 EditMode 41/41·PlayMode 38/38은 사용자의 과거 완료 보고다. 실제 현재 테스트를 찾아 재실행하고 추가/변경한 검사를 별도로 센다.

## 1. 핵심 판정 — 명칭이 아니라 실제 동작

| 항목 | 통과 근거 | 통과로 보지 않는 것 |
|---|---|---|
| 연속 맵 | 같은 플레이어가 동일 탐험 씬에서 실제 좌표로 경계를 지나 이동 | 한 씬 안에 흩어진 방을 순간이동으로 연결 |
| 수직 탐험 | 실제 벽 슬라이드/벽 점프로 오르내리고 랜드마크를 다시 만남 | 평면 복도 끝의 사다리·출구 버튼만 추가 |
| 지름길 | 돌아온 뒤 실제 통로가 열려 이후 왕복 경로가 짧아짐 | 지도 선만 연결하거나 문을 누르면 다른 장소로 이동 |
| 상태 유지 | 경계 통과 전후 상태와 타이머가 이어짐 | 구역 진입 때 모든 대상을 초기 생성 |
| 환경 아트 | 비정형 지형·제단·벽·비밀 입구가 게임에 통합됨 | 예쁜 컨셉아트 파일만 존재하거나 회색 블록에 라벨만 붙임 |
| 레벨 통과 | 게임의 실제 이동·점프·공격·속성·상호작용 입력으로 본선 완주 | 테스트 함수로 해금/열기/텔레포트 후 통과 보고 |

## 2. 회귀 검증 — 바꾸지 않는 것

- [ ] 기본·차지의 기존 R 및 1R 도달거리, 단타 1회, 차지 0.5초, 네 방향 판정 보존.
- [ ] 현재 지상 차지·공중 단타·방향/속성 확정·취소 규칙 보존. 벽 연결에서만 명시한 최소 차이 기록.
- [ ] 검흔 가까운 생성·2초·한 슬롯·생성 ActionId 중복 금지·기존 전달 거리와 지원표 보존.
- [ ] 한 대상 한 의미상 전이, Wet→Dry와 Burning, 수면 Liquid/Frozen, 물에서 만든 얼음과 냉기 흔적 구분 보존.
- [ ] 기본 적 화상 DoT·물 둔화·바람 제어·직접 동결·해제 보존. 새 밸런스 보정 없이 배치만 변경.
- [ ] 실험실의 4속성·더미 편집·Apply/Reset·지원표·한국어 UI·포커스 방지 정상.

## 3. 연속 맵과 상태

- [ ] 본선 Z01~Z06과 S01/S02를 하나의 탐험 씬·공통 좌표에서 실제로 연결.
- [ ] 구역 통과 중 플레이어 재생성·일반 출구 텔레포트·Scene Load·페이드·조작 정지 없음. 메뉴·사망·명시적 리셋은 로그에 별도 사건으로 분리.
- [ ] 플레이어 instance/scene/position·구역 이벤트를 기록하여 연속 이동을 확인. 큰 delta가 발생하면 대시·사망 등 원인을 설명.
- [ ] 구역 양방향 반복 통과에도 원소 해금·열린 길·발견/보상이 복제·되감기되지 않음.
- [ ] 경계 양쪽에 반응 대상과 검흔을 두어 이동 중 상태·전달체·타이머가 초기화되지 않음 확인.
- [ ] 화면 밖에 둔 연소/검흔 수명이 정책대로 진행. 멀리 갔다 돌아와 무한 잔존하지 않음.
- [ ] 탐험 수면은 명시적 구역 리셋 전 유지, 검흔 구조는 기존 수명. 경계 횡단은 해동·슬롯 해제 사건이 아님.
- [ ] 상하 상대 위치가 지도와 실제 월드에서 일치. 발견 전 비밀 공간 전체가 지도에 노출되지 않음.

## 4. 실제 경로와 관문

### 정상 경로 — 외부 또는 게임 입력 계층으로 검사

- [ ] 탐험 새 시작 불1개 → Z02 → Z03 물 획득 → 벽 점프 상층 → Z04 얼음 획득.
- [ ] Z03/Z02 재방문 → 지상 아래 베기로 노출 수면 동결 → 보행 → Z05 바람 획득.
- [ ] 기존 바람 장치/이동체를 활용해 Z06으로 연결 → 안쪽에서 귀환길 개방 → Z01 복귀.
- [ ] 열린 지름길을 반대로 이동해도 실제로 통과. 전후 왕복 경로/이동량 비교를 남김.
- [ ] S01은 기존 불→바람 전달로, S02는 시각 단서와 이동으로 접근하고 안전하게 빠져나옴.

내부 함수로 능력을 지급하거나 위치를 옮기는 검사는 단위/조건 검사로만 표시한다. 정상 경로 증거에 섞지 않는다.
위상 그래프 검사도 수행할 수 있지만 실제 벽 점프·충돌·사거리 검증을 대신하지 않는다.

### 진행 건너뛰기·복구

- [ ] 얼음 해금 전 Z02→Z05를 일반 점프·대시·같은 벽 재점프·반대 벽 교대로 우회 가능한지 실측.
- [ ] 의도한 필수 관문을 막는 장치가 단순 투명벽·순간 능력 차단이 아니라 읽히는 지형/반응 조건인지 확인.
- [ ] 검흔 발판/상자/적을 이용한 루트 건너뛰기도 필요한 범위로 검사. 모든 창의적 우회를 버그로 막기보다 필수 순서 유지 대상과 허용 우회를 구분·기록.
- [ ] 필수 경로가 2초 검흔 발판 묘기나 새 공중 차지에 의존하지 않음.
- [ ] 하층 낙하·물 해동·상자 끼임·가연물 소실 뒤 재설정 또는 대체 경로로 복구 가능.
- [ ] 사망/구역 초기화/탐험 처음부터/실험실 복귀를 각각 검사. 보존할 권능·길·지도와 초기화할 임시 상태가 맞음.
- [ ] 얼음 발판 위에서 구역 초기화해도 플레이어가 물속/벽속에 남지 않음. 안전지점과 카메라 속도·벽 상태 정리.

## 5. 벽 행동

- [ ] 좌우 벽에서 하강+벽 방향 입력 때만 슬라이드. 상승·천장·바닥·적·자기 검흔이 벽으로 오인되지 않음.
- [ ] 벽에서 점프 새 입력 1회당 정확히 한 벽 점프. 점프 홀드로 자동 연속 상승하지 않음.
- [ ] 벽 반대 방향·위로 이탈하고 짧은 재접촉 제한 뒤 기존 공중 제어가 돌아옴.
- [ ] 같은 벽 재접촉/반대 벽 교대·벽 모서리·갱도 상단·경사·착지 전환에서 끼임/무한 속도/떨림 없음.
- [ ] 벽 상태가 대시 무적·대시 횟수·점프 자원을 임의 리셋하지 않음.
- [ ] 벽 접촉 중 단타·대시·피격·사망·지도 열기/닫기에서 상태가 고착되지 않음. UI 해제 뒤 오래된 입력이 재생되지 않음.
- [ ] 실제 벽 동작 수치와 기존 지상 이동·공격 보존 수치를 문서에 기록.

## 6. 아트·카메라·한글

- [ ] 탐험 지형이 격자 네모 반복이 아니라 숲·뿌리·바위·수로의 연결된 형태로 읽힘. 판정의 평탄함은 유지.
- [ ] 표식이었던 제단·귀환 문·비밀 입구가 실제 아트의 비활성/활성·열림/닫힘 상태로 교체됨.
- [ ] 벽 슬라이드/벽 점프에서 손·발·검·스카프가 벽 및 좌우 방향과 맞음. 공중 Idle 복사만으로 동작을 대체하지 않음.
- [ ] 발판 끝·벽면·수면·빙결 충돌과 그림이 맞고 미세 장식 때문에 몸이 걸리지 않음.
- [ ] 기존 캐릭터 정체성·동양풍 도트·픽셀 밀도·검술 보존. 무관한 새 고해상도 화풍으로 교체되지 않음.
- [ ] 카메라 경계 스냅·수직 시야 부족·리스폰 화면 비행·구역 경계 진동 없음.
- [ ] 패럴랙스의 상하좌우 이동·극단 범위·왕복 뒤 원점 드리프트·빈 화면·이음새를 연속 재생으로 검사.
- [ ] 전경이 벽 점프 접촉면·착지점·비밀 단서를 가리지 않고 카메라가 미발견 공간을 누설하지 않음.
- [ ] 지도·새 벽 조작 안내·현재 구역 초기화·체크포인트 UI가 한국어이고 1366×768/1920×1080에서 잘림·누락 없음.

## 7. 실행과 증거

컴파일, EditMode, PlayMode, Windows 빌드, 런타임을 실제로 실행하고 명령·stdout/stderr·종료 코드를 저장한다.
실제 XML에서 total/pass/fail/skip를 기록하고 과거 검사 수를 목표치처럼 맞추지 않는다.

기존 ‘방이 바뀌면 위치/임시 상태를 초기화한다’ 같은 테스트는 새 연속 맵 정책으로 명시 갱신할 수 있다. v02 전환 정책→v03 연속 정책의 의도적 변경임을 문서화한다.
관련 없는 전투·반응·한글·보호 테스트를 실패했다는 이유로 완화/삭제하지 않는다.

Evidence 최소 구성:
- 실제 월드 전체 구조 캡처 또는 현행 레벨 데이터의 좌표도와 핵심 구간 실제 게임 화면. 디버그 전체 지도는 사용자 지도와 구분.
- 본선 전체 루프의 실제 입력 이벤트·플레이어 경로, 정상 구역 통과에서 씬/인스턴스가 유지되는 기록.
- 벽 동작 좌/우 연속 프레임, 긴 수직 구간·하강·지름길 왕복의 짧은 영상 또는 시간순 프레임.
- 수면 동결/보행/해동, 체크포인트·초기화 UI 클릭, 비밀 두 곳의 실제 발견/복귀.
- 충돌 F1 ON 화면과 일반 F1 OFF 화면. 컨셉 그림을 게임 캡처로 등록하지 않음.
- 보호 원본과 이전 빌드의 전후 해시, Git 변경 목록, 신규 아트 경로·사용처.

기존 지원 범위에서 30/60/120 목표 설정의 이동/벽/수명 논리를 비교하고 실제 도달 FPS와 구분한다.
렌더 캡처 없는 짧은 성능 표본과 관찰 시간·해상도·GPU를 기록한다. 장시간 안정성을 보장했다고 하지 않는다.
ComputeBuffer 종료 진단은 원인 미확정으로 보존한다. 새 오류·플레이 중 문제가 있으면 따로 조사하고 숨기지 않는다.
검증용 프로세스는 자신의 PID만 정상 종료한다. 다른 Editor/Hub나 라이선스 프로세스는 건드리지 않는다.

전체 PASS/PARTIAL/BLOCKED와 A/B/C 개별 상태를 구분한다. 유효한 게임은 있으나 필수 아트·시각/실입력 검증이 빠졌으면 PARTIAL, 본선 진행 불능/크래시/빌드 부재는 BLOCKED다.
실제 입력 경로·상태 유지·벽·기본 회귀·아트 통합 검토가 완료되어야 자체 기술 PASS를 보고한다. 이는 사람의 재미·미술 최종 승인과 다르다.

사용자에게 남길 질문은 세 가지로 좁힌다:
1. 공간이 방들의 나열보다 하나의 위아래로 연결된 장소로 느껴지는가?
2. 벽 이동이 자연스럽고, 새 속성을 얻고 돌아올 길이 떠오르는가?
3. 자연형 지형과 추가 아트가 예쁘면서도 밟는 곳·반응 대상·숨은 단서를 읽기 쉬운가?
