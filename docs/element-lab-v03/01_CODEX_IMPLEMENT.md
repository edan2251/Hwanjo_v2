## 4. ‘통짜 맵’의 완료 조건

- 탐험을 시작한 뒤에는 **동일 탐험 씬·동일 플레이어 인스턴스·연속 월드 좌표**로 모든 주요 구역과 비밀 공간을 걸어서 연결한다.
- 구역 경계마다 Scene Load, 출구 텔레포트, 좌표 재배치, 페이드, 화면 고정 전환, 조작 잠금, 오브젝트 재생성을 하지 않는다.
- 시작 메뉴에서 실험실/탐험을 선택하거나 사망·명시적 초기화로 안전 지점에 복귀하는 것은 예외다. 이 예외를 일반 길 이동처럼 쓰지 않는다.
- 구역 ID는 지도 발견·랜드마크 설명·명시적 리셋 범위에만 사용한다. 구역을 바꿨다는 이유로 차지·검흔·젖음·동결·불·지름길을 초기화하지 않는다.
- 화면 밖 상태도 정책대로 유지/시간 경과한다. 오브젝트를 안 보이게 했다고 타이머가 영구 정지하거나 초기 상태가 복제되지 않는다.
- 전체 월드가 단일 씬이어도 내부 계층/프리팹/콜라이더/비주얼 조각은 나눌 수 있다. 하나의 거대한 이미지·Mesh로 만들 필요는 없다.
- 기존 실험실과 v0.1/v0.2 빌드는 보존한다. v0.2 비교 씬은 보존 가능한 한 유지하고, 공유 코드 변경의 영향은 회귀 검증한다.

PowerShell/.NET I/O는 확인된 절대경로를 사용하고, 단순 치환 때문에 파일 인코딩·줄바꿈을 전면 재작성하지 않는다.

## 6. A→B→C 작업 순서

### A. 기준점·이동·레벨 골격

실제 v02 구현·테스트·현재 화면을 최소 확인하고 baseline commit, 사용자 변경, 기존 빌드와 원본 이미지 해시를 기록한다.
현재 이동거리·점프/대시·1R·물 판정·카메라를 측정한다. 02의 지도를 실제 좌표에 맞춰 설계하고 먼저 지형 골격을 만든다.
벽 슬라이드·벽 점프를 최소 추가한다. 벽 이동으로 주요 속성 관문이 우회되는지도 포함해 실제 조작으로 기본 루프를 검증한다.
`docs/V03_LEVEL_DESIGN.md`에 초기 지도·게이트·현재 수치를 기록한다. 정상 구현에서 설계 승인만 기다리며 멈추지 않는다.

### B. 연속 탐험과 진행·지도 연결

출구/방 전환에 묶였던 이동·상태·지도 로직을 연속 맵으로 바꾼다. 새로운 지역 경계는 텔레포트가 아니다.
재방문·속성 획득·지름길·비밀 공간·체크포인트·구역 리셋과 실험실 복귀를 연결한다.
사용자 입력으로 불→물→얼음→물길 재방문→바람→성소 지름길을 통과한다. 내부 함수로 능력을 지급하거나 좌표를 옮긴 검증과 구분한다.
그레이박스에서 통과 불가능한 부분을 먼저 해결한 뒤 아트 배치를 확정한다.

### C. 필요한 아트·벽 동작·카메라 통합

03 기준으로 반복 네모 타일처럼 보이는 지형을 자연형 플랫폼·절벽·뿌리 구조로 다듬고, 단순 표식이었던 제단·지름길·비밀 입구에 실제 환경 아트를 적용한다.
기존 주인공과 검술은 재사용하고 벽 슬라이드/벽 점프의 자세·접촉·작은 효과만 보완한다.
기존 패럴랙스 3층과 댐핑을 연속 수평·수직 공간에 맞춘다. 방별 카메라 스냅·빈 화면·도트 떨림이 남지 않는지 확인한다.
실제 게임의 수평·수직 이동 연속 장면과 핵심 랜드마크를 열어 검수한다. 콘셉트 이미지·파일 수만으로 완료하지 않는다.

### 최종 검증·빌드

04 체크리스트의 회귀·연속 이동·관문 우회·복구·한글 UI·시각 통합을 검사한다.
빌드는 `Builds/ElementLabV03/HwanjoElementLab.exe`, 로그는 `artifacts/element-lab-v03/<run-id>/`에 남긴다.
프로젝트 내 실제 씬 경로와 조작 안내를 README에 적는다. 거대한 새 야간 런처·자동 커밋 게이트는 만들지 않는다.

## 7. 실패 처리·병렬 작업

메인 에이전트가 통합하고 동일 프로젝트의 Unity 검증은 한 번에 하나만 실행한다.
사용 가능한 보조 에이전트는 지도/진행 읽기 검토, 별도 Art/V03 리소스, 테스트 검토로 작업 경계를 나눈다. 같은 Scene/Prefab/Player/튜닝 파일 동시 수정 금지. 도구가 없으면 순차 진행한다.
사소한 지형 좌표·장식 수치는 설계 범위 안에서 선택·기록한다. 실제 권한·사용량·중요 사용자 충돌은 숨기지 않는다.
중단 시 작업을 되돌리지 말고 마지막 단계·재현·로그·재개 위치를 HANDOFF에 남긴다. 전체 작업이 끝났다고 하거나 백그라운드에서 계속할 것처럼 보고하지 않는다.

## 8. 최종 보고 기준

한국어로 A/B/C별 PASS/PARTIAL/BLOCKED, 전체 결과와 근거를 보고한다.

필수 보고: 실제 씬·EXE, 연속 맵 연결·새 벽 조작·지름길·비밀 공간, 기존 규칙 보존, 생성·재사용 아트와 미달 항목, 테스트 수/실패/skip/종료 코드, 사용자 입력 검증·게임 화면, 보호 파일·Git 상태, known issues·미검증.
문서·화면 검수에 통과해도 재미·최종 미술 승인·장시간 안정성은 사람 평가로 남긴다.

유효한 빌드와 필수 기능·아트 통합·실제 경로·시각 자체 검토를 모두 확인해야 전체 PASS다.
아트가 표식·회색 블록으로 남았거나 전체 경로를 실제로 확인하지 못했다면 PARTIAL이다. 빌드가 없거나 본선 진행 불능·크래시가 있으면 BLOCKED다.
기존 ComputeBuffer 종료 경고는 원인·영향을 단정하지 말고 새 오류와 분리한다. 원인을 확인하지 않고 ‘무해함’ 또는 ‘해결됨’으로 처리하지 않는다.
