# C단계 · 실제 플레이 화면의 아트와 움직임 완성

**C단계는 필수 범위다.** A/B가 되었다고 문서에 ‘폴리싱 예정’만 남기고 PASS 처리하지 않는다.
새 아트가 요구 기준에 미달하면 작동 가능한 대안을 남기되 PARTIAL과 누락 항목을 명시한다. 사람의 최종 미술 승인은 별도다.

## 1. 기존 결과를 살리기

사용자는 현재 배경이 마음에 든다고 했다. 기존 실험실 배경의 색감·분위기·주인공 정체성을 보존하면서 깊이·접촉 동작·플랫폼 완성도를 높인다.
수정 전에 clean gameplay 캡처, 좌우 검 공격, 차지, 위/아래 추가 전후를 비교 자료로 남긴다.
원본 5장은 `references/element-lab-v01/`에서 실제로 열어본다. 새로 못 찾았다고 기존 화풍을 무관한 템플릿으로 바꾸지 않는다.

| 원본 | 참조 | 가져오지 않을 것 |
|---|---|---|
| Hwanjo_Reference_Character.png | 검은 묶음머리·붉은 스카프·남색/아이보리·검 여행자 | 새 폼/무기/다른 인물 |
| Hwanjo_Reference_Stage1.png | 청록 숲·이끼·유적·작은 인물 비율 | 보스·스토리보드 컷씬 |
| Hwanjo_Reference_4Concept.png | 동양풍 구조물·거리감 | 4지역 전체·신수 상시 출현 |
| Hwanjo_Reference_VFX1.png | 불 궤적·불티·준비/접촉/회수 대비 | 쌍검·3타 콤보 |
| Hwanjo_Reference_VFX2.png | 베기 방향별 자세·차가운 궤적의 대비 | 대도·백발 폼·호랑이 소환 |

원본 이미지를 실제 게임 sprite sheet로 잘라 그대로 사용하지 않는다. 고해상도 설명판을 48×48로 축소해 캐릭터 제작 완료로 취급하지 않는다.

## 2. 검과 손·몸을 하나의 동작처럼

- 네모 무기 표시를 검날·손잡이·끝이 읽히는 검 이미지로 교체.
- 캐릭터 몸체에 검을 그려 넣거나, 손 앵커에 별도 검 sprite를 연결하는 방식 중 현재 구조에 맞는 최소 변경 선택.
- 별도 레이어여도 손잡이를 쥔 위치·검 회전·몸통 준비/회수·검집 표시가 일치해야 한다.
- 발 피벗·몸 크기·PPU는 동작 중 일관되게. 검을 수납한 상태와 공격 중 중복 표시 금지.
- 대시·피격·사망·메뉴 종료·방 전환 뒤 무기가 공중에 남거나 잘못된 손에 붙지 않는다.
- VFX OFF에서도 자세와 검이 자연스러워야 한다. 광원/블룸/참격으로 임시 네모를 덮는 방식 금지.

## 3. 4방향 애니메이션 범위

프레임별 도트와 필요한 별도 검 레이어를 우선한다. 새 360도 리깅/조준 시스템으로 구조를 갈아엎지 않는다.

| 기본 모션 원형 | 요구 |
|---|---|
| 수평 단타 | 준비→접촉→회수. 좌/우는 시각 반전 허용 |
| 위 단타 | 팔·어깨·검의 위 방향 전용 자세 |
| 아래 단타 | 지상 낮춰 찌르기/베기와 공중 다리 자세. 전체 캐릭터를 회전하지 않음 |
| 수평 차지 해제 | 같은 1R 안에서 차지임을 읽히게 하고 검흔 생성 |
| 위 차지 해제 | 위 방향 자세·검흔 연결 |
| 아래 차지 해제 | 아래 노출면에 적용하는 동작·검흔 연결 |

이 여섯 모션 계열은 **제작 범위 계획**이며 clip 6개만 만들면 됐다는 완료 기준이 아니다. 차지 준비/대기, 지상·공중 연결, Idle/Run/Jump/Fall/Dash/Hit/Death와의 전환은 기존 동작을 활용하되 실제로 확인한다.
좌우는 반전 재사용 가능. 반전은 몸체/검/궤적/손 앵커에 일관되게 적용한다. `SpriteRenderer.flipX`만 바꿨다고 collider나 child anchor가 반전됐다고 가정하지 않는다.
속성 4개마다 몸체 동작을 네 벌 다시 만들지 않는다. 같은 단타/차지 동작을 공유하고 불·물·바람·얼음의 검/궤적/잔흔 표현만 바꾼다.
전체 스프라이트를 90도 돌려 위/아래 베기를 흉내 내거나 같은 자세 복사·이름 바꾸기만으로 동작 완성 처리 금지.
핵심 포즈 우선: 방향·팔·손·검날이 읽히는 접촉 프레임부터 만든 후 준비/회수 연결. 새로운 프레임 수를 채우려고 실제 공격 타이밍을 바꾸지 않는다.

## 4. 속성·반응 시각 표현

불=작은 불꽃/불티, 물=둥근 물결/방울, 바람=가는 방향선, 얼음=각진 서리/결정. 색만으로 구분하지 않는다.
차지 완료 신호는 0.5초와 일치. 큰 참격을 만들어 1R 밖까지 맞힐 것처럼 보이지 않게 한다.
검흔은 가까운 생성 위치·현재 속성·만료 전 약해지는 신호를 표현한다. 플레이어 전체를 가리지 않는다.
물→얼음 구조는 실제로 밟을 수 있는 면과 단순 냉기 흔적을 명확히 다르게 그린다. 충돌이 없는 장식 결정에 플랫폼처럼 단단한 상면을 그리지 않는다.
소화·해동·젖음·건조는 작은 전환 효과를 주되 모든 반응을 폭발로 표현하지 않는다.
DoT마다 Hit Stop·카메라 흔들림 반복 금지. 여러 적 동시 적중으로 시간 정지를 합산하지 않는다.

## 5. 패럴랙스 배경 — 한 테마, 거리 3층

원경(산·먼 누각/하늘), 중경(숲·석조 기둥), 근경 장식(소량 가지·풀). 플레이 지형과 반응 대상은 항상 월드 기준 1:1로 유지한다.
기존 배경이 평면 1장이라면 앞 물체가 움직이며 드러나는 뒤 공간을 채운 레이어를 제작한다. 같은 완성 그림 세 장을 반투명 중첩해 흔드는 것으로 대체하지 않는다.
레이어 위치는 기준 원점+**실제로 움직인 카메라의 위치 차이**에서 계산한다. 프레임마다 작은 이동을 계속 더하는 누적 오차 방식 피함.
임시 parallax factor: 원경0.15 / 중경0.4 / 가까운 비충돌 장식0.7. 이 숫자의 계산 의미를 코드 주석·튜닝에 명시하고 시야에서 조정한다. 게임 지형에 배율 적용 금지.
레이어는 카메라 극단·방 경계·줌 고정 화면을 덮을 여유 폭을 갖는다. 반복 이음새·투명 공백·구멍 검사.
전경이 플레이어·수면·발판 끝·숨은 입구 단서를 가리지 않는다. 추가 거대 입자·어둠으로 정보 손실 금지.

## 6. 카메라 댐핑

기존 카메라 추적 구조를 먼저 확인한다. 새로운 패키지 설치 없이 기존 방식의 최소 변경을 우선.
임시값: 수평 추적 완화 0.12초, 수직 추적이 있으면 0.08초. 0초(즉시 추적) 비교 가능.
캐릭터 입력과 물리에는 댐핑을 넣지 않는다. SmoothDamp 계열은 지연시간만큼 멈췄다가 시작하는 방식이 아니다.
방의 카메라 경계를 적용하고, 작은 방의 최소/최대 clamp가 역전되지 않게 한다. 화면 반폭·반높이를 경계 계산에 반영한다.
리스폰·테스트방 초기화·텔레포트·큰 방 전환에는 추적 위치/velocity를 함께 초기화하여 먼 거리 비행 방지.
점프/낙하에서 착지면이 보이고, 숨겨진 방이 경계 밖으로 미리 노출되지 않아야 한다. 새 줌 연출·과한 시야 선행은 추가하지 않는다.
도트 렌더링과 부드러운 카메라의 떨림 확인. 픽셀 스냅은 표시 위치 문제이고 물리 좌표/사거리를 프레임마다 양자화해 해결하지 않는다.

## 7. 플랫폼과 환경

현재 숲 유적 테마에서 석재·이끼·짧은 목재 연결을 사용. 새 화풍·거대한 지형 종류 추가 금지.
상면/끝/측면/하부·내외부 모서리를 포함한 작은 타일 조합으로 검은 네모 블록 느낌을 없앤다.
그림상 밟는 면과 collider 윗면/끝이 맞아야 한다. 장식 풀·이끼가 발판 길이를 과장하지 않는다.
상호작용 가능한 덩굴/밧줄은 장식과 형태/대비/배치로 구분. 똑같은 덩굴인데 어떤 것은 불에 반응하지 않는 혼란을 피한다.
물·얼음·일반 고체 발판·일방향 발판은 읽히는 차이가 있어야 한다. 이번에 일방향 플랫폼이 필요 없다면 억지 추가하지 않는다.
E01~E06·S01~S02가 같은 방 복제처럼 보이지 않도록 물가·회랑·정원·제단의 작은 랜드마크를 준다.

## 8. 리소스·시간·승인

가능한 내장 이미지 생성/편집 도구를 실제 확인하여 사용. 별도 유료 API·외부 과금·새 프로그램 설치는 사용자 승인 없이 하지 않는다.
제안 작업 한도: 생성/편집 호출 총10회, 같은 산출물2회 이내. 기존 좋은 배경을 통째로 다시 생성하기보다 부족한 레이어·검·방향 포즈를 우선한다.
아트 도구가 없거나 일관성 기준을 못 맞춘 항목은 fallback/누락으로 기록한다. 기능은 검증하되 아트 완료로 위장하지 않는다.
기존 원본 PNG5장·v0.1 생성 아트 원본·빌드를 보존. 교체 리소스는 `Assets/ElementLab/Art/V02/` 등 별도 경로를 우선한다.
문서 manifest에는 파일·생성법·참고 원본·픽셀 크기·pivot/PPU·연결한 동작·검수 상태·fallback 여부 기록.

## 9. C단계 완료 증거

실제 게임으로 촬영해 열어본 자료를 남긴다. 최소:
- v0.1/수정 후 같은 플레이어와 방의 clean 화면 비교.
- 좌우/위/아래 단타의 준비·접촉·회수 연속 프레임. 위/아래는 좌우 보기 모두 검토.
- 차지0.5초→검흔 생성→재타격, 수면 동결→걷기→해동 화면.
- 6개 본선 방과 2개 비밀방의 실제 화면.
- 좌우/상하 카메라 이동 시 parallax와 도트 흔들림을 볼 수 있는 짧은 영상 또는 시간순 연속 프레임. 정지 이미지 한 장은 스크롤 검증으로 세지 않는다.
- 모든 한글 메뉴·더미·반응 도움말·지도·초기화 확인창.
- F1 OFF에서 네모 무기/디버그 도형 없음, F1 ON에서 판정 일치.

자동 검증만으로 아름다움/팀 최종 미술 승인을 선언하지 않는다. 대신 필수 아트 작업을 실제 완료·통합·자체 검토했는지를 근거로 보고한다.
