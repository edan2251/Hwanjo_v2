## 최신 지시와 고정 규칙

사용자의 최신 구체 결정 > 이번 v02 명세 > 현재 v01 구현/튜닝 > 오래된 v01 지시/원본 이미지 속 옛 전투 설명.
이 우선순위는 프로젝트 안전·보호 규칙을 무시하라는 뜻이 아니다. 새로운 상충 사용자 변경이 있으면 문서에 명시하고 필요한 확인만 요청한다.

- 단타/차지 모두 **1R**. 기본 R를 올려서 회피 금지. 1.75R는 이전 버전 기록으로만 유지.
- 이번 권장 시험: 4방향 선택 베기. 360도 자유 조준·원형 광역 공격·8방향 시스템·새 원거리 전용 버튼 없음.
- 단타1회, 0.5초 차지, 4속성 즉시 선택, 검흔 슬롯1개, 임시2초 수명 유지.
- 한 공격이 한 대상 상태를 Wet→Dry→Burning처럼 두 번 변경하지 않음.
- 낮은 물에는 아래 베기를 실제로 닿게 한다. 원거리 자동 타깃이나 지형 관통으로 해결하지 않음.
- 검흔 생성과 기본 재타격을 가깝게. 검흔은 생성 후 세계에 남고 캐릭터를 따라오지 않음.
- 새 반응 목록은 실제 구현/도감/더미 로그가 일치하도록 관리.
- 현행 `docs/PROTOTYPE_SCOPE.md`의 해당 버전 부분만 보완하고 이전 작업 이력은 보존.
- 단타/차지 피해·적 반응·물리 이동은 명시 변경 외에는 유지. 아트·카메라 작업으로 임의 밸런스 변경하지 않음.

## 권한과 범위

허용: `Assets/ElementLab`의 필요한 기존 파일과 새 V02 리소스/씬/테스트, 현행 docs와 README의 실행 안내, 작은 진단 코드, artifacts/Builds 출력.
ProjectSettings는 빌드·입력·레이어에 반드시 필요한 최소 변경만 이유와 diff 기록. 실제 가능하면 빌드 helper에서 씬을 명시해 전역 설정 변경을 줄인다.
별도 Notion/GitHub 원격 문서 수정은 하지 않는다.

금지:
- Git add/commit/push/merge/switch/reset/restore/clean/stash, 브랜치·remote·사용자 계정 변경.
- 원본 PNG, 과거 프롬프트 패키지, Skill/AGENTS 전체 덮어쓰기.
- v0.1 빌드 출력 교체·삭제, 다른 프로젝트/v1 코드 자동 반입.
- Unity/패키지/CLI/OS 설치·업그레이드, 인증·라이선스·보안 정책 변경.
- 다른 작업의 Unity/Hub/Licensing 프로세스 강제 종료 또는 lock 파일 삭제.
- 실패 테스트 삭제·skip·검증값을 버그에 맞게 변경하여 PASS 꾸미기.
- UI 언어를 바꾼다는 이유로 코드·파일명의 전면 한국어 변경.

프로젝트 Unity 실행이 sandbox 밖 사용자 캐시/라이선스 통신 권한을 필요로 하면 필요한 명령의 승인을 요청한다. 스스로 전체 접근/무승인 옵션으로 재실행하지 않는다.
상세 명령·stdout·stderr·exit code는 분리한다. Git 경고가 stdout 파일 목록으로 섞여 ‘삭제’ 판정을 만들지 않는다.
PowerShell과 .NET 상대경로 혼동을 피하고 파일 I/O는 확정된 절대경로 사용. 의미 없는 BOM/빈줄 재작성은 하지 않는다.

## 협업과 실패 처리

한 주 에이전트가 통합하고 Unity 프로세스는 한 프로젝트당 동시에 하나만 실행.
사용 가능한 보조 에이전트는 읽기 전용 검토/테스트 설계 또는 서로 다른 리소스 경로로 제한. 같은 Scene/Prefab/.asset/Player 스크립트를 동시에 쓰지 않는다. 하위 에이전트가 없는 환경이면 순차로 진행.
정상 단계마다 승인용 질문을 추가하지 않고 완료까지 진행한다. 불명확한 비핵심 수치는 명세의 임시안으로 좁게 선택하고 기록한다.
환경·권한·사용량·실제 사용자 충돌이 있으면 숨기지 않고 중단/인계한다. 무한 재시도나 실패 게이트 제거 금지.
도중 중단 시 결과물을 보존하고 HANDOFF에 마지막 완료 단계·실패·재개 지점을 남긴다. 다시 시작하면 완료 단계를 통째로 재구현하지 않는다.
